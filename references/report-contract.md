# 输出契约（索图外勤）

> 候选发现与最终报告的格式。照写，不自由发挥。

## findings/ 单条候选格式

每条候选一个文件：`findings/F<序号>-<短标题>.md`

```markdown
# F3 疑似爆破成功链 — 45.155.20.19 → /api/login

- 级别: high
- 命中模式: 爆破成功链(401×23 → 200)
- 证据: access.log L187720-L189566; 成功行 L189566
- 事实: 2026-08-14 02:11:03~02:19:44 (+0800), 45.155.20.19 对 /api/login
  发起 23 次 401, 02:19:44 出现一次 200
- 疑似: 暴力破解成功
- 不能排除: 正常用户多次输错后登录成功
- 建议复核: 该 IP 归属; 200 之后该会话的操作
- 状态: 待用户裁决
```

## report.md 结构

```markdown
# 排查报告 — <目标目录> — <日期>

## 范围与方法
- 对象: 文件数/总大小/时间覆盖(缺口如实标注)
- 方法: 用了哪些工具(版本), 哪条降级路径(若降级, 写清覆盖边界)
- 环境: OS/shell

## 结论速览
| # | 级别 | 一句话 | 状态 |
每行链到 findings/F*.md。**只允许「疑似/待复核/排除」, 不许「确认」。**

## 时间线(如有)
精确到秒, 每条带证据位置。

## 零命中清单
扫了哪些模式、多少行、零命中——这是有效结论。

## 产物清单
本排查创建的所有文件: 绝对路径 + 一句话说明 + 「可安全删除的缓存」标注。
**提醒用户自行决定是否清理; 你不删任何东西。**

## 局限与建议
- 本次分析无平台证据链背书, 正式案件建议回索图重做;
- 待用户补充的信息(如有): 列表。
```

## 对话内措辞纪律

- 说「疑似」「不能排除」「建议复核」，不说「确认是」「肯定是」；
- 时间一律带时区（源数据是什么时区写什么，不确定就标「时区未知」）；
- 机器标识写 IP/主机名，不写「受害机」「攻击者的机器」这种角色词——角色是结论，结论归人。
